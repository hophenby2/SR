# SR Test Bridge Protocol v2

The bridge protocol version is 2. It is a synchronous TCP server using UTF-8
JSON Lines (JSONL): one JSON object followed by `\n` in each direction. It
binds to `127.0.0.1:24816` by default. It accepts one client and never sends
unsolicited messages, so one request always has exactly one response with the
same `id`.

The module is inert until `SRTestBridge.install(...)` is called. The companion
`init.lua` only installs it when the global `SR_TEST_MODE` is `true`, or the
environment variable `SR_TEST_MODE` is `1`, `true`, `yes`, or `on`. A missing or
disconnected client leaves the original frame loop, renderer, and keyboard
input active. In test mode, bridge installation waits up to 30 seconds for the
initial client by default. This lets lockstep/headless interception become
active before a runtime can block in its first Render/Present call. Set
`SR_TEST_STARTUP_ACCEPT_TIMEOUT=0` to restore nonblocking startup.

## Catalog

The live catalog is the authoritative mapping from a one-based attack ordinal
to SR's raw boss-card index. It is generated by `compat/spell_practice.lua`
from the same card tables used to register Spell Practice entries.

```json
{"id":1,"command":"catalog"}
```

The response below is abridged; the real `scenarios` and `attacks` arrays
contain all entries described by their counts:

```json
{
  "id":1,
  "ok":true,
  "catalog":{
    "schema_version":1,
    "scenario_count":22,
    "attack_count":53,
    "scenarios":[
      {
        "scenario":"okuu:Lunatic",
        "label":"Lunatic 5 Boss",
        "attack_count":4,
        "attacks":[
          {"scenario":"okuu:Lunatic","attack":1,"card_index":2,"label":"Lunatic 5 Boss #1"}
        ]
      }
    ],
    "attacks":[
      {"scenario":"okuu:Lunatic","attack":1,"card_index":2,"label":"Lunatic 5 Boss #1"}
    ]
  }
}
```

The bundled SR catalog is expected to contain 22 scenarios and 53 attacks.
Clients must still enumerate `catalog.attacks` rather than hard-code the
scenario/card mapping. Movement cards, dialogue cards, and generated
one-second end markers are excluded. The catalog payload currently retains its
own schema version 1; this is independent of bridge protocol v2 and live-engine
report schema v2.

## Reset

`attack` is the one-based attack ordinal shown by SR's Spell Practice menu. It
does not count movement cards, dialogue cards, or one-second end markers.

```json
{"id":1,"command":"reset","scenario":"okuu:Lunatic","attack":3,"seed":42,"player":"reimu_player","options":{}}
```

The bridge starts `Spell Practice@Spell Practice`, advances one engine frame,
and replies with its initial observation (abridged below):

```json
{"id":1,"ok":true,"reset":{"scenario":"okuu:Lunatic","attack":3,"card_index":4,"seed":42,"player":"reimu_player"},"observation":{}}
```

Supported reset options are:

- `include_previous`: include the preceding boss movement/card.
- `attack_is_card_index`: interpret `attack` as the raw `cards` index.
- `hidden_route`: set `lstg.var.hidden_route` before stage initialization.
- `lifeleft`, `bomb`, `power`, `faith`, `score`: override practice resources
  after stage initialization.
- `player_protect_frames`: raise the newly created player's `protect` counter
  to at least this many frames after stage initialization. The engine content
  regression uses this instead of changing collision logic.

The bridge seeds both THlib's `ran` generator and Lua's `math.random` generator.

## Step

```json
{"id":2,"command":"step","action":{"move_x":-1,"move_y":1,"slow":true,"shoot":true,"spell":false},"repeat":3}
```

`move_x` and `move_y` are clamped to `[-1, 1]`. Values below `-0.25` press
left/down and values above `0.25` press right/up. The Boolean fields control
focus, shooting, and bomb/spell. The action is held for `repeat` logical frames.
The response is sent after the final frame, or earlier when the episode stops:

```json
{"id":2,"ok":true,"observation":{"episode_frame":4,"terminated":false}}
```

Default stop conditions are a player hit, 7200 episode frames, a stage change,
or all enemies disappearing after at least one enemy has been observed. The
no-enemy decision reads the authoritative, unfiltered `GROUP_ENEMY` and
`GROUP_NONTJT` object pools. It deliberately does not use the visible
observation arrays, because a live off-screen or temporarily hidden boss must
not end an episode. A terminated episode rejects further `step` requests until
`reset`.

## Other Commands

```json
{"id":3,"command":"observe"}
{"id":4,"command":"ping"}
{"id":5,"command":"display","render":true,"every":12}
{"id":6,"command":"close"}
{"id":7,"command":"shutdown"}
```

`observe` returns state without advancing logic. `display` enables or disables
`RenderFunc` after a headless reset. Its optional `every` value is clamped to
`[1, 600]` and presents one sampled state per that many logical frames. Visible
lockstep never presents the same logical state twice while it waits for the
next client action. `ping` returns protocol and
frame metadata, the supported commands/actions, run identities, and an
operating-system/runtime identity:

```json
{
  "id":4,
  "ok":true,
  "protocol":2,
  "frame":0,
  "action_names":["move_x","move_y","slow","shoot","spell"],
  "commands":["ping","catalog","reset","step","observe","display","close","shutdown"],
  "session_id":"engine-v2-a",
  "process_nonce":"table: 0x01234567@1785312000.000000",
  "runtime_identity":{
    "process_id":12345,
    "executable_path":"C:\\path\\to\\LuaSTGSub.exe",
    "executable_crc32":"0123abcd",
    "source_crc32":{
      "root.lua":"0123abcd",
      "_editor_output.lua":"0123abcd",
      "compat/init.lua":"0123abcd",
      "compat/combo.lua":"0123abcd",
      "compat/gameplay.lua":"0123abcd",
      "compat/spell_practice.lua":"0123abcd",
      "compat/player/marisa.lua":"0123abcd",
      "compat/player/reimu.lua":"0123abcd",
      "compat/player/sakuya.lua":"0123abcd",
      "compat/background/effects.lua":"0123abcd",
      "compat/background/stage6bg.lua":"0123abcd",
      "compat/background/stg2bg.lua":"0123abcd",
      "compat/background/stg3bg.lua":"0123abcd",
      "compat/background/stg4bg.lua":"0123abcd",
      "compat/background/stg5bg.lua":"0123abcd",
      "compat/background/stg6bg.lua":"0123abcd",
      "compat/testing/bridge.lua":"0123abcd",
      "compat/testing/init.lua":"0123abcd"
    }
  }
}
```

`session_id` is supplied by `SR_TEST_SESSION_ID` and identifies the requested
test run. `process_nonce` is generated by each bridge instance and detects
accidental reuse of one bridge instance. `runtime_identity.process_id` is the
real Windows process ID obtained through Win32 FFI. The executable path and
CRC32 identify the loaded engine binary. `source_crc32` is computed by the
running Lua process over the 18 listed, actually loaded SR Lua files under
`SR_TEST_SOURCE_ROOT`.

The Python runner independently computes CRC32 and SHA-256 for those same
runtime files. A live report is rejected when the runtime CRC map differs from
the local files. It also records `implementation_sha256`, a stable source-tree
fingerprint over all shipped `stg_lab` Python modules. Formal cross-process
acceptance requires distinct nonempty session IDs and process nonces, distinct
positive OS process IDs, equal executable CRCs, equal runtime Lua CRC maps,
equal local source SHA-256 maps, and the current implementation fingerprint.
`close` disconnects the client. `shutdown` exits LuaSTG only when
`allow_shutdown`/`SR_TEST_ALLOW_SHUTDOWN` is enabled.

Errors always use this shape:

```json
{"id":2,"ok":false,"error":"episode is terminated; reset is required"}
```

## Observation

The observation contains only primitive JSON values and these main fields:

- `frame`, `episode_frame`, `terminated`, `termination_reason`
- `stage`: stage name/timer and spell-practice scenario/card index
- `world`: playfield and player movement bounds
- `player`: position, motion, collider, death/protection and weapon cooldowns
- `enemy_bullets`, `enemies`, `nontjt_enemies`, `indestructibles`
- `lasers`: a subset of the object arrays, with straight-laser geometry or
  bent-laser sampled points
- `resources` and `counts`

Hidden, deleted, and off-playfield objects are omitted by default. Straight
lasers are retained when their swept segment intersects the playfield, even if
their origin is outside it. Each object includes position, velocity,
acceleration, collision shape, image/class identifiers, and relevant HP or
laser fields when available. `lasers` intentionally duplicates records from
their owning collision group.

`enemy_bullets`, `enemies`, `nontjt_enemies`, `indestructibles`, and `lasers`
are always JSON arrays, including when empty; every corresponding
`counts.<name>` must equal the array length. Catalog `scenarios`, top-level
`attacks`, nested scenario `attacks`, and bent-laser `points` likewise retain
array identity. This is an explicit wire contract: clients must reject an
empty JSON object (`{}`) where an array (`[]`) is required.

## Environment

| Variable | Default | Meaning |
| --- | --- | --- |
| `SR_TEST_MODE` | unset | Explicitly enable the bridge |
| `SR_TEST_HOST` | `127.0.0.1` | Listen address |
| `SR_TEST_PORT` | `24816` | Listen port; `0` requests an ephemeral port |
| `SR_TEST_SEED` | `1` | Initial deterministic seed |
| `SR_TEST_HEADLESS` | `1` | Suppress `RenderFunc` while connected |
| `SR_TEST_LOCKSTEP` | `1` | Advance only for reset/step while connected |
| `SR_TEST_MAX_FRAMES` | `7200` | Episode time limit |
| `SR_TEST_SESSION_ID` | unset | Caller-supplied run identity returned by `ping` |
| `SR_TEST_STARTUP_ACCEPT_TIMEOUT` | `30` in test mode, otherwise `0` | Seconds to wait for the first client during installation |
| `SR_TEST_SOURCE_ROOT` | `game/mod/SR_Subterrain_Reanimation_v100` | Filesystem root used for runtime Lua CRC32 fingerprints |
| `SR_TEST_ALLOW_SHUTDOWN` | unset | Permit the shutdown command |

Programmatic callers may override all defaults documented in `bridge.lua`.
For an installed `stg-lab` wheel, `STG_LAB_MOD_ROOT` can point the Python-side
fingerprint verifier at this mod directory. Without it, the verifier searches
the current directory and its parents.

## Engine Verification Status

CrossOver 26.3 with the DXVK graphics backend can start the real executable,
load the complete SR resources/scripts and bridge, and open the TCP listener.
The wined3d path fails in framebuffer creation with
`GL_INVALID_FRAMEBUFFER_OPERATION (0x506)`; DXMT reaches the Lscreen render
target but fails `IDXGISurface` acquisition with `E_NOINTERFACE`. These backend
diagnostics are not themselves an engine acceptance result.

The final protocol-v2 DXVK runs used sessions `engine-v2-a` and `engine-v2-b`
and distinct Win32 PIDs 212 and 204. Both reported executable CRC32
`8844e525`; their 18-entry runtime Lua CRC32 maps matched the local files, and
their 18-entry local SHA-256 maps matched the current tree. Each retained all
53 attacks in 22 scenarios, 300 logical frames per attack plus the reset
observation, and no errors. Their file SHA-256 values are respectively
`ac7996a2ee92417e08deda8ff5e86d3a0937278f7bb15a772e53089275a0abeb`
and `8d692aa4a4f79ed6de0d701d628ebbbbc64cce624f016deb12d198dec6e5b257`.
The combined report matched all 53 attacks and 15,953 hash positions, records
`passed: true` and `engine_verified: true`, and has SHA-256
`a2a7cca87e6e416c43b963483e450b5a1e000cdfcdbd32eadbdb16d5e19ea1d2`.
All three reports bind implementation SHA-256
`ba7f4d2ee9fe5bf232f264a180a51280657f007629a54fd36c3f4884ca966cb9`.
Earlier protocol-v1 reports remain invalid for this gate.

The v2 claim remains limited to headless Spell Practice content regression. It
does not imply rendered-frame comparison, a full-stage clear, or real-engine
AI survival evaluation.
