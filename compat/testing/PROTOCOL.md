# SR Test Bridge Protocol v2

The bridge protocol version is 2. It is a synchronous TCP server using UTF-8
JSON Lines (JSONL): one JSON object followed by `\n` in each direction. It
binds to `127.0.0.1:24816` by default. It accepts one client and never sends
unsolicited messages, so one request always has exactly one response with the
same `id`.

The module is inert until `SRTestBridge.install(...)` is called. The companion
`init.lua` only installs it when the global `SR_TEST_MODE` is `true`, or the
environment variable `SR_TEST_MODE` is `1`, `true`, `yes`, or `on`. A missing or
disconnected client leaves the original frame loop, renderer, and keyboard
input active. In test mode, bridge installation waits up to 30 seconds for the
initial client by default. This lets lockstep/headless interception become
active before a runtime can block in its first Render/Present call. Set
`SR_TEST_STARTUP_ACCEPT_TIMEOUT=0` to restore nonblocking startup.

## Catalog

The live catalog is the authoritative mapping from a one-based attack ordinal
to SR's raw boss-card index, and from a full-stage name to a registered stage.
It is generated by `compat/spell_practice.lua` from the same card and stage
tables used by the game.

```json
{"id":1,"command":"catalog"}
```

The response below is abridged; the real `scenarios` and `attacks` arrays
contain all entries described by their counts:

```json
{
  "id":1,
  "ok":true,
  "catalog":{
    "schema_version":1,
    "scenario_count":22,
    "attack_count":53,
    "stage_count":10,
    "scenarios":[
      {
        "scenario":"okuu:Lunatic",
        "label":"Lunatic 5 Boss",
        "attack_count":4,
        "attacks":[
          {"episode_kind":"attack","scenario":"okuu:Lunatic","attack":1,"card_index":2,"label":"Lunatic 5 Boss #1","completion_reason":"attack_complete"}
        ]
      }
    ],
    "attacks":[
      {"episode_kind":"attack","scenario":"okuu:Lunatic","attack":1,"card_index":2,"label":"Lunatic 5 Boss #1","completion_reason":"attack_complete"}
    ],
    "stages":[
      {"episode_kind":"stage","stage":"Stage 1@Normal","stage_index":1,"difficulty":"Normal","label":"Normal Stage 1","completion_reason":"stage_complete"}
    ]
  }
}
```

The bundled SR catalog is expected to contain 22 scenarios, 53 attacks, and 10
Normal/Lunatic Stage 1-5 entries. Clients must enumerate `catalog.attacks` and
`catalog.stages` rather than hard-code either mapping. Movement cards, dialogue
cards, and generated one-second end markers are excluded. The catalog payload
retains schema version 1; this is independent of bridge protocol v2 and
live-engine report schemas.

## Reset

`attack` is the one-based attack ordinal shown by SR's Spell Practice menu. It
does not count movement cards, dialogue cards, or one-second end markers.

```json
{"id":1,"command":"reset","scenario":"okuu:Lunatic","attack":3,"seed":42,"player":"reimu_player","options":{}}
```

The bridge starts `Spell Practice@Spell Practice`, advances one engine frame,
and replies with its initial observation (abridged below):

```json
{"id":1,"ok":true,"reset":{"scenario":"okuu:Lunatic","attack":3,"card_index":4,"seed":42,"player":"reimu_player"},"observation":{}}
```

Supported reset options are:

- `include_previous`: include the preceding boss movement/card.
- `attack_is_card_index`: interpret `attack` as the raw `cards` index.
- `hidden_route`: set `lstg.var.hidden_route` before stage initialization.
- `lifeleft`, `bomb`, `power`, `faith`, `score`: override practice resources
  after stage initialization.
- `player_protect_frames`: raise the newly created player's `protect` counter
  to at least this many frames after stage initialization. The engine content
  regression uses this instead of changing collision logic.
- `player_collidable` and `player_ghost`: training-field capture controls that
  can prevent player collisions or move the player to `GROUP_GHOST`. Any run
  using them is training-only and is ineligible for strict validation.

The bridge seeds both THlib's `ran` generator and Lua's `math.random` generator.

## Full-stage Reset

`reset_stage` starts a registered full stage without routing it through Spell
Practice:

```json
{"id":8,"command":"reset_stage","stage":"Stage 1@Normal","seed":42,"player":"reimu_player","options":{}}
```

The reply includes `episode_kind="stage"`, stage name/index, difficulty, seed,
and player. Empty enemy pools between waves do not complete a stage. After at
least one active enemy has been observed, a non-final stage completes only when
the engine reaches its unique registered same-difficulty successor. Stage 5
completes only on a menu transition. A wrong stage transition, window/engine
exit, player hit, or time limit is not `stage_complete`.

Every full-stage reset calls THlib's `item.PlayerInit` and applies that stage's
registered isolated/practice resource table before switching stages. This is required
for a fresh process that enters generated Stage 2-5 directly: those stage init
functions assume Stage 1 already initialized the complete player-data schema.
It also makes isolated stage resets independent of earlier episodes in the same
engine process. Unless `options.hidden_route` is supplied, an isolated stage
reset clears stale hidden-route state.

## Campaign Reset

`reset_campaign` starts a continuous native Stage 1-5 run for one registered
difficulty:

```json
{"id":9,"command":"reset_campaign","difficulty":"Lunatic","seed":42,"player":"reimu_player","options":{}}
```

The bridge validates that the live catalog contains exactly one registered,
contiguous Stage 1-5 sequence whose stages share one native stage group and
menu target. It initializes Stage 1 once with `stage.Set(..., "none")`; all
later transitions must come from the game's own `stage.group.FinishStage()`.
`lstg.var`, lives, bombs, power, faith, score, and gameplay-earned
`hidden_route` state remain live across those transitions. The bridge clears
`hidden_route` only at campaign start.

Campaign `options` must be an empty object. `replay_name` is rejected because a
valid THlib campaign replay needs a separate writer and initial-state record for
each native stage; concatenating all five input streams into one stage record
would create an invalid replay.

The reset response identifies the first stage and fixed campaign size:

```json
{"id":9,"ok":true,"reset":{"episode_kind":"campaign","difficulty":"Lunatic","stage_index":1,"stage_name":"Stage 1@Lunatic","stage_count":5,"seed":42,"player":"reimu_player"},"observation":{}}
```

Campaign observations additionally contain this state (abridged after the
Stage 1 to Stage 2 transition):

```json
{
  "campaign":{
    "schema_version":1,
    "difficulty":"Lunatic",
    "stage_index":2,
    "stage_name":"Stage 2@Lunatic",
    "stage_count":5,
    "stages_completed":1,
    "completed_stages":[{
      "stage_index":1,
      "stage_name":"Stage 1@Lunatic",
      "completion_episode_frame":3600,
      "active_content_seen":true,
      "resources":{"lifeleft":2,"bomb":3,"power":245,"faith":1200,"graze":8,"score":10000},
      "hidden_route":true
    }],
    "active_content_seen":true,
    "stage_active_content_seen":false,
    "stage_transition_count":1,
    "transitions":[{
      "from_stage_index":1,
      "from_stage_name":"Stage 1@Lunatic",
      "to_stage_index":2,
      "to_stage_name":"Stage 2@Lunatic",
      "episode_frame":3600,
      "active_content_seen":true,
      "resources":{"lifeleft":2,"bomb":3,"power":245,"faith":1200,"graze":8,"score":10000},
      "hidden_route":true
    }],
    "initial_resources":{"lifeleft":2,"bomb":3,"power":100,"faith":0,"graze":0,"score":0},
    "resources":{"lifeleft":2,"bomb":3,"power":245,"faith":1200,"graze":8,"score":10000},
    "initial_hidden_route":false,
    "hidden_route":true,
    "campaign_complete":false
  }
}
```

The authoritative `GROUP_ENEMY`/`GROUP_NONTJT` pools must contain active
content at least once in every stage before its transition is accepted. Legal
Stage 1 to 2, 2 to 3, 3 to 4, and 4 to 5 transitions update the campaign state
in the same `step` observation and do not terminate the episode. Clients can
detect a boundary by an increment of `stage_transition_count` and clear only
their scene-local geometry/tracks. A skipped, reversed, early, or unexpected
transition terminates with `campaign_stage_changed`.

The Stage 5 to native menu transition records the fifth completed stage and
terminates with `campaign_complete`. At that terminal boundary
`observation.stage.name` is the menu, while `campaign.stage_index=5` and
`campaign.stage_name` retain the completed Stage 5 identity;
`stages_completed=5`, `stage_transition_count=5`, and
`campaign_complete=true`. A hit remains `player_hit`, the frame limit covers
the entire continuous run and remains `time_limit`, and an engine/window exit
remains `engine_exit`.

## Replay Playback Reset

`reset_replay` loads one existing native THlib replay for read-only analysis:

```json
{"id":10,"command":"reset_replay","path":"../slot3.rep"}
```

The path is interpreted by the LuaSTG process and may be relative to its working
directory or absolute. The bridge is bound to localhost and treats its client as
trusted; this command can read any path available to that process. It never
writes, moves, or replaces the input replay.

The bridge calls `plus.ReplayManager.ReadReplayInfo` and accepts only an `STGR`
file-version-1 replay containing exactly one
`Spell Practice@Spell Practice` stage and at least one input frame. It verifies
the declared frame region through exact EOF before loading it with
`stage.Set("Spell Practice@Spell Practice", "load", path)`. The serialized
practice state must resolve either its direct `sc_pr_data` identity or its legacy
global `sc_index` against the currently registered spell-practice table.

The reset advances one logical frame, so the response observation is taken after
the first recorded input byte has been consumed. Its metadata binds the loaded
header and verified frame extent:

```json
{
  "id":10,
  "ok":true,
  "reset":{
    "episode_kind":"replay",
    "scenario":"okuu:Lunatic",
    "card_index":4,
    "seed":10292,
    "player":"Reimu",
    "replay":{
      "schema_version":1,
      "path":"../slot3.rep",
      "file_version":1,
      "game_name":"SR-master",
      "game_version":1,
      "group_finish":0,
      "user_name":"HT",
      "stage_name":"Spell Practice@Spell Practice",
      "stage_player":"Reimu",
      "random_seed":10292,
      "frame_count":3388,
      "frame_data_position":834,
      "frame_bytes_verified":3388,
      "file_size":4222,
      "crc32":"9fa7c77e",
      "scenario":"okuu:Lunatic",
      "card_index":4,
      "spell_practice_index":50
    }
  },
  "observation":{}
}
```

For subsequent frames the client should send a neutral `step` action. THlib's
active `replayReader` replaces `KeyState`, so client action fields cannot alter
recorded movement, focus, shooting, or spell input. A repeat larger than the
remaining replay is stopped at the terminal frame. Normal result reasons such
as `player_hit`, `attack_complete`, and `stage_changed` take priority when
observed; if no more specific result occurs, consuming the declared final input
frame terminates with `replay_exhausted`. This endpoint supports only a single
Spell Practice stage, not full-stage or campaign replay playback.

## Step

```json
{"id":2,"command":"step","action":{"move_x":-1,"move_y":1,"slow":true,"shoot":true,"spell":false},"repeat":3}
```

`move_x` and `move_y` are clamped to `[-1, 1]`. Values below `-0.25` press
left/down and values above `0.25` press right/up. The Boolean fields control
focus, shooting, and bomb/spell. The action is held for `repeat` logical frames.
The response is sent after the final frame, or earlier when the episode stops:

```json
{"id":2,"ok":true,"observation":{"episode_frame":4,"terminated":false}}
```

Default stop conditions are a player hit, 7200 episode frames, or a stage
change. Attack episodes additionally stop when all enemies disappear after at
least one enemy has been observed. That decision reads the authoritative,
unfiltered `GROUP_ENEMY` and `GROUP_NONTJT` pools, not the visible observation
arrays, because a live off-screen or temporarily hidden boss must not end an
attack. Full-stage episodes ignore no-enemy gaps and apply the normal-successor
contract above. Campaign episodes apply the continuous state machine above. A
terminated episode rejects further `step` requests until `reset`,
`reset_stage`, `reset_campaign`, or `reset_replay`.

## Other Commands

```json
{"id":3,"command":"observe"}
{"id":4,"command":"ping"}
{"id":5,"command":"display","render":true,"every":12}
{"id":6,"command":"close"}
{"id":7,"command":"shutdown"}
```

`observe` returns state without advancing logic. `display` enables or disables
`RenderFunc` after a headless reset. Its optional `every` value is clamped to
`[1, 600]` and remains a protocol compatibility hint. Native LuaSTG clears and
presents its swap-chain target around every `RenderFunc` call, so visible
lockstep redraws the current logical state on every native render pass instead
of submitting black buffers while it waits for the next client action. `ping`
returns protocol and
frame metadata, the supported commands/actions, run identities, and an
operating-system/runtime identity:

```json
{
  "id":4,
  "ok":true,
  "protocol":2,
  "frame":0,
  "action_names":["move_x","move_y","slow","shoot","spell"],
  "commands":["ping","catalog","reset","reset_stage","reset_campaign","reset_replay","step","observe","display","save_replay","close","shutdown"],
  "session_id":"engine-v2-a",
  "process_nonce":"table: 0x01234567@1785312000.000000",
  "runtime_identity":{
    "process_id":12345,
    "executable_path":"C:\\path\\to\\LuaSTGSub.exe",
    "executable_crc32":"0123abcd",
    "source_crc32":{
      "root.lua":"0123abcd",
      "_editor_output.lua":"0123abcd",
      "compat/init.lua":"0123abcd",
      "compat/combo.lua":"0123abcd",
      "compat/gameplay.lua":"0123abcd",
      "compat/spell_practice.lua":"0123abcd",
      "compat/player/marisa.lua":"0123abcd",
      "compat/player/reimu.lua":"0123abcd",
      "compat/player/sakuya.lua":"0123abcd",
      "compat/background/effects.lua":"0123abcd",
      "compat/background/stage6bg.lua":"0123abcd",
      "compat/background/stg2bg.lua":"0123abcd",
      "compat/background/stg3bg.lua":"0123abcd",
      "compat/background/stg4bg.lua":"0123abcd",
      "compat/background/stg5bg.lua":"0123abcd",
      "compat/background/stg6bg.lua":"0123abcd",
      "compat/testing/bridge.lua":"0123abcd",
      "compat/testing/init.lua":"0123abcd"
    }
  }
}
```

`session_id` is supplied by `SR_TEST_SESSION_ID` and identifies the requested
test run. `process_nonce` is generated by each bridge instance and detects
accidental reuse of one bridge instance. `runtime_identity.process_id` is the
real Windows process ID obtained through Win32 FFI. The executable path and
CRC32 identify the loaded engine binary. `source_crc32` is computed by the
running Lua process over the 18 listed, actually loaded SR Lua files under
`SR_TEST_SOURCE_ROOT`.

The Python runner independently computes CRC32 and SHA-256 for those same
runtime files. A live report is rejected when the runtime CRC map differs from
the local files. It also records `implementation_sha256`, a stable source-tree
fingerprint over all shipped `stg_lab` Python modules. Formal cross-process
acceptance requires distinct nonempty session IDs and process nonces, distinct
positive OS process IDs, equal executable CRCs, equal runtime Lua CRC maps,
equal local source SHA-256 maps, and the current implementation fingerprint.
`close` disconnects the client. `shutdown` exits LuaSTG only when
`allow_shutdown`/`SR_TEST_ALLOW_SHUTDOWN` is enabled.

Errors always use this shape:

```json
{"id":2,"ok":false,"error":"episode is terminated; reset is required"}
```

## Observation

The observation contains only primitive JSON values and these main fields:

- `frame`, `episode_frame`, `terminated`, `termination_reason`
- `stage`: stage name/timer, episode kind/scenario, and practice card index
- `world`: playfield and player movement bounds
- `player`: position, motion, collider, death/protection and weapon cooldowns
- `enemy_bullets`, `enemies`, `nontjt_enemies`, `indestructibles`
- `lasers`: a subset of the object arrays, with straight-laser geometry or
  bent-laser sampled points
- `resources` and `counts`
- `campaign`: continuous Stage 1-5 progress, transition/resource snapshots,
  and hidden-route state; present only for campaign episodes

Hidden, deleted, and off-playfield objects are omitted by default. Straight
lasers are retained when their swept segment intersects the playfield, even if
their origin is outside it. Each object includes position, velocity,
acceleration, collision shape, image/class identifiers, and relevant HP or
laser fields when available. `lasers` intentionally duplicates records from
their owning collision group.

`enemy_bullets`, `enemies`, `nontjt_enemies`, `indestructibles`, and `lasers`
are always JSON arrays, including when empty; every corresponding
`counts.<name>` must equal the array length. Catalog `scenarios`, top-level
`attacks`, nested scenario `attacks`, `stages`, bent-laser `points`, and campaign
`completed_stages`/`transitions` likewise retain array identity. This is an
explicit wire contract: clients must reject an empty JSON object (`{}`) where
an array (`[]`) is required.

## Environment

| Variable | Default | Meaning |
| --- | --- | --- |
| `SR_TEST_MODE` | unset | Explicitly enable the bridge |
| `SR_TEST_HOST` | `127.0.0.1` | Listen address |
| `SR_TEST_PORT` | `24816` | Listen port; `0` requests an ephemeral port |
| `SR_TEST_SEED` | `1` | Initial deterministic seed |
| `SR_TEST_HEADLESS` | `1` | Suppress `RenderFunc` while connected |
| `SR_TEST_LOCKSTEP` | `1` | Advance only for reset/step while connected |
| `SR_TEST_MAX_FRAMES` | `7200` | Episode time limit |
| `SR_TEST_SESSION_ID` | unset | Caller-supplied run identity returned by `ping` |
| `SR_TEST_STARTUP_ACCEPT_TIMEOUT` | `30` in test mode, otherwise `0` | Seconds to wait for the first client during installation |
| `SR_TEST_SOURCE_ROOT` | `game/mod/SR_Subterrain_Reanimation_v100` | Filesystem root used for runtime Lua CRC32 fingerprints |
| `SR_TEST_ALLOW_SHUTDOWN` | unset | Permit the shutdown command |

Programmatic callers may override all defaults documented in `bridge.lua`.
For an installed `stg-lab` wheel, `STG_LAB_MOD_ROOT` can point the Python-side
fingerprint verifier at this mod directory. Without it, the verifier searches
the current directory and its parents.

## Engine Verification Status

CrossOver 26.3 with the DXVK graphics backend can start the real executable,
load the complete SR resources/scripts and bridge, and open the TCP listener.
The wined3d path fails in framebuffer creation with
`GL_INVALID_FRAMEBUFFER_OPERATION (0x506)`; DXMT reaches the Lscreen render
target but fails `IDXGISurface` acquisition with `E_NOINTERFACE`. These backend
diagnostics are not themselves an engine acceptance result.

The final protocol-v2 DXVK runs used sessions `engine-v2-a` and `engine-v2-b`
and distinct Win32 PIDs 212 and 204. Both reported executable CRC32
`8844e525`; their 18-entry runtime Lua CRC32 maps matched the local files, and
their 18-entry local SHA-256 maps matched the current tree. Each retained all
53 attacks in 22 scenarios, 300 logical frames per attack plus the reset
observation, and no errors. Their file SHA-256 values are respectively
`ac7996a2ee92417e08deda8ff5e86d3a0937278f7bb15a772e53089275a0abeb`
and `8d692aa4a4f79ed6de0d701d628ebbbbc64cce624f016deb12d198dec6e5b257`.
The combined report matched all 53 attacks and 15,953 hash positions, records
`passed: true` and `engine_verified: true`, and has SHA-256
`a2a7cca87e6e416c43b963483e450b5a1e000cdfcdbd32eadbdb16d5e19ea1d2`.
All three reports bind implementation SHA-256
`ba7f4d2ee9fe5bf232f264a180a51280657f007629a54fd36c3f4884ca966cb9`.
Earlier protocol-v1 reports remain invalid for this gate.

The v2 claim remains limited to headless Spell Practice content regression. It
does not imply rendered-frame comparison, a full-stage clear, or real-engine
AI survival evaluation.
